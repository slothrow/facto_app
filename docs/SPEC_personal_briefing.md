# 학사운영 앱 상세 기획서 (6단계: 개인브리핑)

> 앞 문서: SPEC_briefing.md (지금의 브리핑 = 이번 단계부터 "전체브리핑")
> 이번 범위: 아이 이름이 들어간 "개인브리핑" 화면, 개인 문구 관리, 부르는 이름, 아이별 확인 → 보내기
> 범위 밖: AI 문장 생성, 아이별로 다른 문장 고르기(문장 모음)

## 1. 용어
| 화면 표시 | 코드명 | 뜻 |
|---|---|---|
| 전체브리핑 | briefing kind `class` | 지금까지의 브리핑. 같은 반 아이 모두에게 같은 문구 |
| 개인브리핑 | briefing kind `personal` | 같은 반 문구에 아이 이름만 넣어 아이별로 보내는 문구 |
| 개인 문구 | `personal_briefing_texts` | 코드별 개인브리핑 문구. `{이름}` 자리를 포함 |
| 부르는 이름 | `students.call_name` | 문구의 `{이름}` 자리에 들어가는 이름(예: 하솜이, 선우) |

## 2. 실제 보내는 순서
전체브리핑 → (갤러리에서 사진) → 개인브리핑. 개인브리핑은 그때그때 보내므로 앱은 순서를 강제하지 않는다. 전체브리핑을 아직 안 보낸 아이에게는 "전체브리핑 아직 안 보냄" 안내만 작게 표시.

## 3. 부르는 이름

### 3.1 자동 기본값 (학생 정보에 call_name이 비어 있을 때)
- 이름 글자 수로 성을 뺀다: 3글자 → 앞 1글자 제외, 4글자 → 앞 2글자 제외, 2글자 → 그대로.
- 남은 이름의 마지막 글자에 받침이 있으면 "이"를 붙인다. 받침 판정: `(글자코드 − 0xAC00) % 28 ≠ 0`.
- 예: 최하솜 → 하솜이, 김선우 → 선우, 김리원 → 리원이, 이안 → 이안이, 남궁민수 → 민수
- 원장님이 직접 고친 값이 있으면 그 값을 쓴다.

### 3.2 조사 보정
- 부르는 이름은 보통 모음으로 끝나므로 문구는 "{이름}는 / {이름}가 / {이름}를 / {이름}와 / {이름}예요"처럼 쓴다.
- 직접 고친 부르는 이름이 받침으로 끝나면(예: "별님") 바로 뒤 조사를 자동 보정: 는→은, 가→이, 를→을, 와→과, 예요→이에요, 로→으로(ㄹ 받침 제외).
- 테스트: "{이름}는 오늘" + 하솜이 → "하솜이는 오늘", + 별님 → "별님은 오늘". "찾아보는 {이름}입니다" + 선우 → "찾아보는 선우입니다".

### 3.3 입력·수정 위치
- 학생 카드 기본 정보에 "부르는 이름" 칸(자동값이 회색으로 보이고, 고치면 저장).
- 개인브리핑 아이 카드에서 이름을 탭해 바로 수정(학생 정보에 저장).
- 설정 → "부르는 이름 확인": 재원생 전체를 한 화면에 나열해 한 번에 검토·수정.

## 4. 개인 문구 관리
- 브리핑 탭 [문구 관리] 상단 전환: **[전체 문구] [개인 문구]**. 개인 문구도 전체 문구와 같은 단계별 격자(단원 12 × 주 4), 채워진/빈 칸, 진행률.
- 테이블 `personal_briefing_texts(code pk, text, updated_at, updated_by)`. 코드당 문구 1개. 같은 반 아이 모두 같은 문구에 이름만 다르다.
- 편집기: [이름 넣기] 버튼으로 커서 위치에 `{이름}` 삽입. 저장할 때 `{이름}`이 없으면 "이름 자리가 없습니다. 그대로 저장할까요?" 확인.
- 일괄 가져오기: 전체 문구와 같은 방식(코드, 문구). 가져올 대상(전체/개인)을 화면에서 선택. 문구 안 `{이름}` 유지.

## 5. 개인브리핑 화면

### 5.1 진입
- 브리핑 탭 상단 전환: **[전체브리핑] [개인브리핑]**. 날짜·반 선택은 두 화면이 공유(전환해도 유지).
- 반 시간 버튼의 진행 표시: "전체 3/4 · 개인 2/4".

### 5.2 화면 구성
- 상단: 오늘 코드(큰 글씨) + 개인 문구 원문(`{이름}` 강조). [수정] → 개인 문구 저장소 수정(다음에도 적용). 문구가 없으면 그 자리에서 작성.
- 아이 목록: 전체브리핑과 같은 명단(그날 기준 반 명단 − 결석, [+ 아이 추가]로 넣은 아이 포함).

### 5.3 아이별 진행: 확인 → 보내기
각 아이 카드는 세 상태를 가진다.
1. **확인 전**: 부르는 이름이 들어간 완성 문장 미리보기(이름 부분 강조). 버튼 **[확인]** 만 활성, [보내기]는 비활성(회색).
   - 미리보기를 탭하면 **이 아이에게만** 적용되는 수정이 가능(저장소 문구는 바뀌지 않음).
   - 이름이 어색하면 이름을 탭해 부르는 이름 수정 → 미리보기 즉시 갱신.
2. **확인됨**: [보내기] 활성. 다시 수정하면 확인 전으로 돌아간다.
3. **보냄**: ✓와 보낸 시각. 다시 탭하면 "보냄 취소" 확인.
- [보내기] 동작은 전체브리핑과 동일: 카톡 검색어 클립보드 복사 → `navigator.share({text})` → 완료 시 기록, 취소면 기록 안 함.
- 확인 상태는 화면을 벗어나도 그날·그 반 안에서는 유지(로컬 저장으로 충분).

## 6. 기록
- `briefings`에 `kind text not null default 'class'` 추가, 기존 행은 'class'. 고유키를 (date, class_id, student_id, kind)로 변경.
- 개인브리핑 기록의 text_snapshot = 실제로 보낸 완성 문장(이름 포함, 아이별 수정 반영).
- 학생 카드 "배운 내용": 날짜 · 코드 · 전체 ✓ · 개인 ✓. 개인 ✓를 누르면 보낸 문장 보기.
- 반 상세 브리핑 현황: "전체 4/4 · 개인 3/4".

## 7. 데이터 모델 추가
| 테이블/컬럼 | 용도 |
|---|---|
| `personal_briefing_texts` | 코드별 개인 문구 |
| `briefings.kind` | 'class'(전체) / 'personal'(개인) |
| `students.call_name` | 부르는 이름(비면 자동값) |
- 새 테이블 RLS + `private.is_member()`. 백업 내보내기에 포함.

## 8. 순수 함수와 테스트 (src/engine/personalBriefing.ts)
- `defaultCallName(name)`: 3.1 예시 전부
- `renderPersonal(template, callName)`: `{이름}` 치환 + 3.2 조사 보정, `{이름}`이 여러 번 나와도 모두 치환
- 결석 아이는 개인브리핑 명단에서 제외, [+ 아이 추가] 아이는 포함

## 9. 확인 필요 사항
- 두 글자 이름은 "이안이"처럼 이름 전체 + "이"를 기본으로 함. 다르게 부르는 아이는 부르는 이름에서 수정.

## 10. 구현하며 정한 것 (27단계, 2026-11-16)
모호했던 점은 아래처럼 정해서 구현했다. 다르게 원하면 알려 주면 바꾼다.
1. **베이직 반의 개인 문구**: 베이직은 단원 코드가 없어 격자가 없다. 개인 문구는 전체브리핑 기록과 같은 코드("베이직 · 제목")를 키로 저장하고, 브리핑 화면(개인브리핑)에서 그 자리에서 작성한다. 문구 관리 → 개인 문구의 베이직 탭은 이 안내만 보여 준다.
2. **1글자·5글자 이상 이름**: 성을 빼지 않고 그대로 쓰고, 받침이 있으면 "이"를 붙인다(외국 이름 등은 부르는 이름에서 고친다). 한글이 아닌 글자로 끝나면 "이"를 붙이지 않는다.
3. **조사 보정**은 `{이름}` 바로 뒤 글자에만 적용한다(는·가·를·와·예요·로). "{이름}이/{이름}은"처럼 받침용 조사로 쓴 문구는 바꾸지 않는다.
4. **이 아이에게만 수정한 문장**은 확인 상태와 함께 이 기기에 그날·그 반 단위로 저장한다(서버 저장 없음). 보내면 그 문장이 기록(text_snapshot)에 남는다.
5. **보냄 상태**에서는 문장을 고칠 수 없다. 다시 보내려면 [보냄 취소] 후 수정 → 확인 → 보내기.
6. **PC처럼 공유 창이 없는 곳**: 전체브리핑과 같이 완성 문장을 복사하고 "보냄으로 기록할까요?"를 묻는다.
7. **하단 탭 이름**은 "브리핑" 그대로 두고, 탭 안의 화면·문구·기록 글자를 "전체브리핑/개인브리핑"으로 나눈다.
8. **기록 종류**: 예전 기록(kind 없음)은 모두 전체브리핑. 같은 날·반·아이에 전체 1건 + 개인 1건까지.
