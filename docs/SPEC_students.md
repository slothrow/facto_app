# 학사운영 앱 상세 기획서 (2단계: 반·학생·대기자·결석)

> 1단계 문서(docs/SPEC.md)에 이어지는 문서. 용어는 CLAUDE.md 용어 사전을 따른다.
> 이번 범위: 반 관리, 학생 관리(학생 카드·상담 기록·가져오기), 대기자·체험수업, 결석 체크.
> 범위 밖(다음 단계): 보강 매칭(같은 주차 반 찾기, 토요 보강 슬롯), 반 편성 시뮬레이터, 할 일·알림.

## 1. 운영 전제
- 원장 1명, 교실 1개 → **같은 요일에 수업 시간이 겹치는 반은 존재할 수 없다.**
- 수업 길이는 50분 고정(상수 `CLASS_MINUTES = 50`). 시작 시간은 10분 단위.
- 반의 회차 일정은 1단계 엔진의 요일반(track) 일정을 그대로 따른다. 반이 속한 요일의 회차 = 그 반의 회차.

## 2. 학년 계산

### 2.1 학년도와 표기
- 학년도: 3월 1일 ~ 다음 해 2월 말. `학년도 = (월 >= 3) ? 연도 : 연도 - 1`
- 학년 표기는 유치원식. `n = 학년도 - 출생연도 + 보정값`
  | n | 4 | 5 | 6 | 7 | 8 | 9 | 10 |
  |---|---|---|---|---|---|---|---|
  | 학년 | 5세 | 6세 | 7세 | 초1 | 초2 | 초3 | 초4 |
- n이 범위 밖이면 "운영 대상 외"로 표시(삭제하지 않음).
- 보정값: 조기입학 +1, 유예 −1. 학생 정보에서 수동 입력.

### 2.2 생일이 없을 때
- 생일이 없으면 등록할 때 입력한 학년과 그 시점의 학년도를 저장하고, 거기서부터 같은 방식으로 자동 진급시킨다.
- 생일을 나중에 입력하면 생일 기준 계산으로 바뀐다. 기존 학년과 다르면 알려준다.

### 2.3 반 학년도 자동 진급
- 반은 "기준 학년도 + 학년"을 저장하고, 표시 학년은 학생과 같은 방식으로 자동 계산한다.
  예: 2026학년도 7세반 → 2027년 3월부터 초1반.
- 3월이 되면 반 목록 상단에 "새 학년도로 바뀌었습니다. 반 학년을 확인하세요" 안내를 1회 띄운다.

### 2.4 테스트 기준
- 생일 2020-05-01: 2026-11-05 → 7세, 2027-02-28 → 7세, 2027-03-01 → 초1
- 생일 2022-01-10: 2026-11-05 → 5세
- 생일 2016-12-31: 2026-11-05 → 초4, 2027-03-01 → 운영 대상 외
- 생일 2020-05-01 + 보정 −1: 2027-03-01 → 7세

## 3. 반

### 3.1 항목
| 항목 | 필수 | 설명 |
|---|---|---|
| 요일 | O | 월~금 |
| 시작 시간 | O | 10분 단위. 저장은 24시간제 `HH:MM`, 화면은 "오후 4:30"처럼 |
| 학년 | O | 5세·6세·7세·초1·초2·초3·초4 중 선택 (기준 학년도와 함께 저장) |
| 별칭 | | 선택. 이름은 자동 생성: "화 4:30 초2" (+ 별칭) |
| 개설일 / 폐반일 | | 반은 삭제하지 않고 폐반 처리. 지난 출석 기록 보존 |
| 메모 | | |

### 3.2 규칙
- 정원: 기본 최대 4명. 5번째 학생을 넣으면 "정원 4명을 넘습니다. 5명으로 진행할까요?" 확인 후 허용. 6명 이상은 불가.
- 2명 미만인 반은 경고 배지.
- 시간 겹침: 같은 요일, 운영 중인 반끼리 `[시작, 시작+50분)` 구간이 겹치면 **저장 불가**.
- 교체 시간: 앞 반 종료와 다음 반 시작 사이가 10분 미만이면 경고(저장은 가능).
- 학생 학년과 반 학년이 다르면 경고만 표시(막지 않음).
- 테스트 기준(같은 요일):
  - 16:30 반 + 17:30 반 → 정상(간격 10분)
  - 16:30 반 + 17:20 반 → 경고(간격 0분)
  - 16:30 반 + 17:10 반 → 저장 불가(겹침)

### 3.3 반 배정 이력
- 학생과 반의 관계는 기간으로 저장: `enrollments(student_id, class_id, start_date, end_date)`.
- 반 이동 시:
  - 적용일 기본값 = 새 반 요일의 "다음 수업월 1주" 날짜(1단계 엔진으로 계산). 직접 날짜 지정도 가능.
  - 이전 배정은 적용일 전날로 종료.
  - 학생의 상담 기록에 "반 이동" 기록을 자동 추가(어느 반 → 어느 반, 적용일).
- 특정 날짜의 반 명단 = 그 날짜를 포함하는 배정 중 학생 상태가 그날 재원인 학생.

### 3.4 화면
- 반 목록: 요일별 묶음 → 시간순. 각 줄에 학년, 인원(예: 3/4), 경고 배지, 대기자 해당 수(예: "대기 2").
- 주간 시간표 보기: 요일×시간 격자. 폰에서는 요일 탭 전환, 태블릿·PC에서는 전체 격자.
- 반 상세: 현재 명단, 학생 추가/이동/빼기, 반 정보 수정, 폐반.

## 4. 학생

### 4.1 항목 (이름만 필수, 나머지는 모두 비워도 됨)
| 구분 | 항목 |
|---|---|
| 기본 | 이름*, 성별, 생일, 학년(생일 없을 때), 학년 보정값, 다니는 학교·유치원 |
| 연락처 | 학생 본인 연락처 / 학부모 연락처 최대 2개(이름, 관계: 엄마·아빠·기타, 번호, 대표 여부) |
| 주소 | 자유 입력 칸 하나 |
| 일정 | 등록일, 첫 수업일(첫 배정 반의 첫 회차 날짜를 자동 제안) |
| 상태 | 재원 / 휴원(시작~종료) / 퇴원(날짜, 사유) |
| 가능 시간 | 요일별 체크 + "몇 시 이후 가능"(예: 화 15:00 이후) |
| 형제자매 | 다른 학생과 연결(양방향) |
| 특이사항 | 학생 카드 맨 위에 항상 보이는 고정 메모 |

### 4.2 상담 기록
- 날짜별로 쌓이는 기록: 날짜, 유형(신규 상담 / 정기 상담 / 학부모 요청 / 반 이동 / 기타), 내용, 다음 연락일(선택).
- 최신순 표시. 반 이동 기록은 자동 생성(3.3).

### 4.3 학생 카드 화면
- 상단: 이름, 학년, 현재 반, 상태 배지, 특이사항.
- **대표 연락처 큰 버튼: [전화] (`tel:`) [문자] (`sms:`).** 다른 연락처도 탭하면 전화.
- 섹션: 기본 정보 / 반 이력 / 상담 기록 / 결석 기록(월별 횟수 + 날짜 목록).
- 전화번호는 숫자만 저장하고 `010-1234-5678` 형식으로 표시.

### 4.4 학생 목록
- 이름 검색(초성 검색 지원: "ㄱㅅㅇ" → 김선우), 필터(상태, 학년, 요일, 반 미배정, 확인 필요).
- 기본은 재원 학생만 표시.

### 4.5 삭제
- 기본은 퇴원 처리(기록 보존).
- 완전 삭제는 학생 카드 맨 아래 "개인정보 완전 삭제" → 이름을 다시 입력해야 실행되는 2단계 확인. 관련 상담·결석·배정 기록도 함께 삭제.

## 5. 입력을 쉽게 하는 기능

### 5.1 엑셀/CSV 붙여넣기 가져오기
- 엑셀에서 복사한 표나 CSV 텍스트를 붙여 넣으면 → 열 매칭 화면 → 미리보기 → 가져오기.
- 열 이름이 아래와 같으면 자동 매칭: 이름, 학년, 생일, 성별, 학교, 학부모1 관계, 학부모1 연락처, 학부모2 관계, 학부모2 연락처, 주소, 등록일, 요일, 시작시간, 반학년, 상태, 메모, 확인필요.
- 요일+시작시간이 있으면 그 반에 배정. 반이 없으면 새로 만듦(반 학년 = 반학년 열).
- 같은 이름이 이미 있으면 미리보기에서 "중복 의심"으로 표시하고 건너뛰기/새로 추가 중 선택.
- `확인필요 = Y`인 학생은 "확인 필요" 태그를 달아 가져온다. 태그는 학생 카드에서 원장이 해제.

### 5.2 초기 명단
- `data/initial_roster.csv`(손글씨 시간표 사진에서 읽어낸 명단)를 5.1 가져오기 기능으로 넣는다.
- 반 학년은 사진의 손글씨 메모 기준이며 기준 학년도는 2026으로 가정한다(12장 확인 필요).
- 시작 시간은 사진 왼쪽 시간 기준(13:30, 14:30, 15:30, 16:30, 17:30), 50분 수업.

### 5.3 폰 연락처에서 가져오기
- 연락처 입력 칸 옆 [연락처에서 선택] 버튼: Contact Picker API(`navigator.contacts.select(['name','tel'])`).
- 지원하지 않는 브라우저(PC 등)에서는 버튼을 숨기고 직접 입력.

### 5.4 빠른 등록
- 학생 추가 화면 첫 단계는 이름·학년·반만. [저장] 후 "나머지 정보 입력하기"로 이어서 작성하거나 나중에.

## 6. 대기자

### 6.1 항목
이름*, 학년(또는 생일), 학부모 연락처(이름·관계·번호), 희망 요일·시간, 문의일, 유입 경로(지인 소개 / 블로그 / 전단 / 기타), 진행 단계, 메모.

### 6.2 진행 단계
문의 → 체험 예약 → 체험 완료 → 등록 / 포기. 단계 변경 날짜를 기록.

### 6.3 빈자리 매칭
- 조건: 운영 중인 반 중 인원 < 4, 반 학년 = 대기자 학년, 대기자 희망 요일·시간과 맞음(희망 시간이 비어 있으면 학년만 비교).
- 반 목록에 "대기 N", 대기자 목록에 "가능한 반 N" 표시. 탭하면 해당 목록.

### 6.4 등록 전환
- [등록하기] → 대기자 정보를 채운 학생 추가 화면 → 저장하면 대기자는 "등록" 단계로 바뀌고 학생과 연결.

## 7. 체험수업 (기록 기능만)
- 항목: 날짜, 반(선택), 대상(대기자 연결 또는 이름 직접 입력), 메모.
- 대기자에 연결되면 대기자 단계를 "체험 예약"으로 자동 변경.
- 해당 날짜의 결석 체크 명단에 "체험" 태그로 표시. 인원 수 표시에는 포함한다(5명 한도 확인용).

## 8. 결석 체크
- 진입: 회차 계획 달력에서 날짜 탭 → 바텀시트에 "이 날 수업 반" 목록 추가 → 반 탭 → 명단.
- 앱 첫 화면(또는 회차 계획 상단)에 **[오늘 출석]** 바로가기.
- 명단: 그날 기준 반 명단(3.3) + 그날 체험 학생. **기본은 전원 출석, 결석인 아이만 탭해서 표시**(다시 탭하면 해제).
- 저장 데이터는 결석만: `absences(date, class_id, student_id)`. 사유·연락 시점은 받지 않는다.
- 공휴일·휴원·비운 날짜에는 반 목록 대신 "수업 없음" 표시.
- 지난 날짜와 미래 날짜 모두 체크 가능(미리 연락받은 결석).
- 학생 카드에 월별 결석 횟수와 날짜 표시.
- 보강 연결은 다음 단계(결석 기록과 날짜별 수업월·주차 정보로 같은 주차 반을 찾을 예정).

## 9. 화면 구조
하단 탭: **회차 계획 / 반·학생 / 달력 만들기 / 설정**
- 반·학생 탭 상단 전환: [반] [학생] [대기자]
- 체험수업은 대기자 화면과 날짜 바텀시트에서 접근.

## 10. 데이터 모델 (Supabase)
| 테이블 | 주요 컬럼 |
|---|---|
| `app_members` | user_id pk (auth.users 참조), display_name, role |
| `classes` | id, weekday, start_time, grade_code, grade_basis_year, alias, opened_on, closed_on, memo |
| `students` | id, name, gender, birthday, grade_code, grade_basis_year, grade_adjust, school, student_phone, guardians jsonb(최대 2개: name, relation, phone, is_primary), address, registered_on, first_class_on, status, status_from, status_to, leave_reason, availability jsonb, notice(특이사항), needs_review bool |
| `student_siblings` | student_id, sibling_id |
| `enrollments` | id, student_id, class_id, start_date, end_date null |
| `counseling_notes` | id, student_id, date, type, content, next_contact_on |
| `waitlist` | id, name, grade_code, grade_basis_year, birthday, guardian jsonb, wish jsonb, inquired_on, source, stage, stage_history jsonb, memo, student_id null |
| `trial_lessons` | id, date, class_id null, waitlist_id null, name, memo |
| `absences` | date, class_id, student_id (pk 세 개 묶음) |
- 모든 테이블: created_at, updated_at, updated_by.
- 값 형식(6단계 결정):
  - `grade_code` = 2.1의 n(4=5세 … 10=초4). `grade_basis_year`는 그 학년을 매긴 학년도.
  - `weekday` 1=월 … 5=금. `start_time`은 `HH:MM` 문자열(10분 단위).
  - `status`: active(재원) / paused(휴원) / left(퇴원). 상담 `type`: new / regular / parent / move / other.
  - 대기자 `stage`: inquiry / trial_booked / trial_done / enrolled / dropped. `source`: referral / blog / flyer / other.
  - `availability`, `wish`: `{ "요일번호": "HH:MM 이후" 또는 null(아무 때나) }`. 없는 요일은 불가.
  - 형제자매는 한 쌍을 한 줄로 저장(작은 id가 student_id).
  - 학생 완전 삭제 시 배정·상담·결석·형제 기록은 함께 삭제(cascade), 대기자의 학생 연결은 해제.
- 마이그레이션: `supabase/migrations/20261105*`. 백업 복원용 `replace_roster(p_data)` 함수로 2단계 데이터를 한 번에 교체.
- 1단계 테이블과 같은 방식으로 Repository 계층을 거친다.

## 11. 보안 (실제 아이들 개인정보가 들어가는 단계)
현재 상태: Supabase + Vercel 배포 완료, 계정 2개(원장, 개발자)만 생성.
- Supabase Auth 설정에서 **새 사용자 가입 허용이 꺼져 있는지** 확인.
- 이중 잠금: 가입이 꺼져 있어도, 모든 테이블 RLS를 "로그인 + `app_members`에 등록된 사용자"로 제한.
  - `private.is_member()` 함수(security definer, `auth.uid()`가 app_members에 있는지 확인)를 만들고 모든 정책에서 사용.
    (처음엔 public에 만들었으나 API로 노출된다는 Security Advisor 경고 때문에 private 스키마로 옮김, 2026-11-05)
  - app_members 등록·삭제는 대시보드 SQL Editor에서만(`supabase/members.sql.example`).
  - 1단계 테이블 정책도 같은 방식으로 교체.
- 모든 테이블 RLS 켜짐 확인. 대시보드의 Security Advisor 경고 0개 목표. (단, "유출 비밀번호 검사"는 유료 플랜 기능이라 무료 플랜에서는 경고 1개가 남는다)
- 프론트엔드·Vercel 환경변수에는 URL과 anon(publishable) key만. **service_role(secret) key는 절대 `VITE_` 변수나 코드에 넣지 않는다.**
- 학생 이름·연락처를 URL, 콘솔 로그, 에러 메시지에 넣지 않는다(URL에는 id만).
- Vercel 미리보기 배포 주소도 같은 DB를 보지만 로그인 없이는 아무것도 안 보이는지 확인.
- 백업: 무료 플랜은 백업 보장이 약하다. 설정의 "백업 내보내기"에 2단계 데이터를 포함하고, 월 1회 백업을 할 일로 안내.
- 개인정보는 필요한 만큼만: 주소는 자유 입력, 주민번호 등은 받지 않는다. 입학원서의 개인정보 수집·이용 동의(14세 미만은 학부모 동의)는 운영 측에서 확인.
